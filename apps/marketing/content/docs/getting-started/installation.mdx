Zyron is a desktop workspace for coding agents. Installing Zyron gives you the workspace; provider runtimes and model access still come from the coding-agent tools and accounts you already use.

## Choose the right installer

Download the latest stable build from the [Zyron download page](/install). If the automatic download is unavailable, open [GitHub Releases](https://github.com/itsKyze/zyron/releases) and select the asset for your system.

| Platform               | Download             |
| ---------------------- | -------------------- |
| macOS on Apple Silicon | Arm64 `.dmg`         |
| macOS on Intel         | x64 `.dmg`           |
| Windows                | x64 `.exe` installer |
| Linux on x86_64        | `x86_64` `.AppImage` |
| Linux on ARM64         | `arm64` `.AppImage`  |

The download page offers both Linux builds; pick `ARM64` if `uname -m` prints `aarch64`.

<Callout type="info" title="Zyron does not include a model subscription">
  Zyron uses provider runtimes installed on your machine. Install and authenticate at least one
  provider—such as Claude Code, Codex, OpenCode, Cursor, or another supported runtime—before
  starting your first task.
</Callout>

## Install Zyron

<Steps>
<Step>

### Download the application

Use the [download page](/install) or an official GitHub release. Avoid third-party download mirrors.

</Step>
<Step>

### Complete the platform installation

Open the downloaded installer and complete the normal installation flow for your operating system.

On Linux, your desktop environment may require making the AppImage executable before opening it:

```bash
chmod +x Zyron*.AppImage
```

AppImages also need FUSE 2. If the AppImage does not start, install your distribution's FUSE 2
package (`fuse2` on Arch, `libfuse2t64` on Ubuntu 24.04+ and Debian trixie+, `libfuse2` on older
Debian and Ubuntu releases) or extract it once:

```bash
./Zyron*.AppImage --appimage-extract
./squashfs-root/zyron
```

</Step>
<Step>

### Install and authenticate a provider

Follow the provider's official installation and sign-in process. Zyron does not copy an account from another machine or replace the provider's own authentication.

Open a fresh terminal and confirm that the provider can start successfully outside Zyron. This separates provider installation problems from Zyron configuration problems.

</Step>
<Step>

### Launch Zyron and check the provider

Open Zyron, go to provider settings, and confirm that the runtime is detected and available. Zyron discovers the models and options exposed by the installed runtime, so the choices can vary by provider version, account, and subscription.

</Step>
<Step>

### Add a project

Choose a local project folder. A Git repository is strongly recommended because it enables branches, worktrees, diffs, commits, pushes, and pull-request workflows.

</Step>
</Steps>

## When a provider is not detected

Work through these checks in order:

1. Open a new terminal window.
2. Confirm that the provider executable runs there.
3. Confirm that the provider is authenticated.
4. Check whether Zyron offers a custom binary-path setting for that provider.
5. Restart Zyron after changing your `PATH` or installing a new runtime.
6. Continue with [Troubleshooting](/docs/troubleshooting) if it remains unavailable.

Zyron normalizes the environment available to the desktop process, but provider installations and shell configurations differ across operating systems.

## Updating Zyron

Packaged builds use Zyron's desktop updater. When an update cannot be applied automatically, download the newest installer and install it over the existing application.

The application bundle and local workspace data are stored separately. Even so, keep important work committed to Git before updating an early release.

## Run without the desktop shell

Each GitHub release also includes `zyron-server-<version>.tar.gz` for a headless web installation. It requires a supported Node.js runtime and a production dependency install; it is not a standalone executable or a replacement for provider authentication.

Follow the [Headless server guide](/docs/workflows/headless-server) for extraction, startup, readiness checks, data-directory ownership, and remote-access policy. Start loopback-only and do not expose the raw server port without deliberate authentication and trusted transport.

<Callout type="warn" title="Zyron is under active development">
  Zyron changes quickly. Keep valuable work committed and review release notes before relying on a
  new workflow for important repositories.
</Callout>

## macOS minimum in 1.0.9

Zyron requires **macOS 13 or later** for its bundled native tools. Stable 1.0.9 packages declare that minimum and updater feeds refuse the update on older macOS systems. Choose the installer matching your processor. Packaged startup checks on macOS 15 do not establish runtime behavior on every macOS 13 configuration.
